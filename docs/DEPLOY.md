# פריסה: מהקוד הזה עד הבוט על pingwin.co.il

GTM הוא הצעד האחרון ולוקח חמש דקות. לפניו צריך שהבוט ירוץ על שרת עם כתובת
HTTPS קבועה — GTM רק מזריק שורת סקריפט לדף, הוא לא מריץ שרתים.

```
[הקוד ב-GitHub] → (1) שרת עם HTTPS → (2) .env → (3) בדיקה → (4) תג ב-GTM → (5) GA4 → (6) פיילוט
```

---

## 1. שרת

צריך מקום שמריץ Node 18+ ברציפות. שלוש אפשרויות, מהקלה ליקרה בזמן:

| איפה | מתאים כש | איך |
|---|---|---|
| **Railway / Render** | אין לכם sysadmin — הכי מהיר | מחברים את ריפו GitHub, הם בונים ומריצים `npm start` לבד, HTTPS אוטומטי |
| **VPS** (Hetzner/DigitalOcean) | רוצים שליטה מלאה | `git clone`, `npm ci`, `pm2 start server/server.js`, nginx + certbot |
| **שרת קיים של פינגווין** | כבר יש תשתית | אותו דבר, מול מי שמנהל אותה |

בכל מקרה: תת-דומיין ייעודי, למשל `bot.pingwin.co.il` (רשומת DNS מסוג A/CNAME
לשרת). מומלץ מאחורי Cloudflare — אז גם `TRUST_PROXY=1` ב-.env.

הפעלה מחדש אחרי עדכון: `git pull && npm ci && pm2 restart` (או deploy אוטומטי
ב-Railway/Render בכל push).

## 2. `.env` בשרת

```bash
PORT=8787
ALLOWED_ORIGINS=https://www.pingwin.co.il,https://pingwin.co.il   # חובה בפרודקשן
TRUST_PROXY=1                     # רק אם מאחורי Cloudflare/nginx

OPENAI_API_KEY=sk-...             # אופציונלי: בלי מפתח הבוט עובד במצב offline
OPENAI_MODEL=gpt-5.6-luna
DAILY_BUDGET_USD=5                # מעל זה ממשיך לענות בחינם עד חצות

TURNSTILE_SITEKEY=0x...           # אופציונלי, חינם — חוסם בוטים
TURNSTILE_SECRET=0x...
LEAD_WEBHOOK_URL=https://...      # אופציונלי: לידים למערכת של פינגווין
LEAD_WEBHOOK_SECRET=...
```

## 3. בדיקה לפני GTM

```
https://bot.pingwin.co.il/healthz     → {"ok":true,"mode":"openai","version":"0.2.0"}
https://bot.pingwin.co.il/            → דף הדמו עם הווידג'ט
```
אם `/healthz` לא עונה — אין טעם להמשיך ל-GTM.

## 4. התג ב-GTM

1. GTM → **Tags → New → Tag Configuration → Custom HTML**
2. להדביק את בלוק ה-`<script>` מתוך `public/gtm-tag.html`
3. להחליף `BOT_HOST` ל-`https://bot.pingwin.co.il` ולוודא ש-`BOT_VERSION`
   תואם ל-`version` שמופיע ב-`/healthz`
4. **"Support document.write" — לא מסומן**
5. Triggering → **All Pages** (לפיילוט: טריגר Page View עם תנאי URL contains
   על עמוד אחד בלבד)
6. שם התג: `Pingwin Ski Bot` → **Save**
7. **Preview** — נכנסים לאתר דרך חלון ה-preview, מוודאים שהבועה מופיעה ושיחה
   שלמה עובדת → **Submit → Publish**

בכל פריסה עתידית של הווידג'ט: להעלות `BOT_VERSION` בתג ולפרסם מחדש — כך
דפדפנים לא מגישים גרסה ישנה מה-cache.

### 4ב. תג שני — מילוי מראש של טופס ההזמנה

בלי התג הזה כפתור "המשך להזמנה" ינחת על דף המלון הנכון, אבל **ריק** —
הלקוח יקליד מחדש תאריכים, נוסעים וחדר. עם התג, הכל כבר בפנים.

1. GTM → **Tags → New → Custom HTML**
2. להדביק את הבלוק השני מתוך `public/gtm-tag.html` (מסומן "תג שני")
3. להחליף `BOT_HOST` ו-`BOT_VERSION` בדיוק כמו בתג הראשון
4. Triggering → **All Pages** (או Page View עם URL contains `siteID=`)
5. שם התג: `Pingwin Booking Prefill` → Save → Submit → Publish

**איך זה עובד:** הבוט מוסיף לכתובת פרמטרים בשם שלנו בלבד
(`pwfrom`, `pwtill`, `pwad`, `pwkids`, `pwroom`, `pwpans`). הסקריפט מחכה
ל-`orderMan` שהאתר יוצר, קורא ל-`setDates()` ואז ל-`loadRoom()`, ומוסיף
מעל הטופס שורה שמסבירה ללקוח שהפרטים מולאו מהצ'אט ושאפשר לשנות.

**מה הוא לא עושה:** לא ממציא. חדר שהוא לא מצליח לזהות בוודאות בשם —
נשאר לבחירת הלקוח, והתאריכים עדיין מתמלאים. בגלישה רגילה, בלי הפרמטרים
שלנו, הוא יוצא מיד ולא נוגע בכלום.

**בדיקה:** לפתוח דף מלון עם `&pwfrom=30.01.2027&pwtill=06.02.2027&pwad=3`
בסוף הכתובת. התאריכים צריכים להתמלא לבד.

## 5. GA4 (אופציונלי, מומלץ)

הווידג'ט דוחף אירוע אחד ל-dataLayer, בלי שום מידע אישי:

```js
{ event: 'pw_bot', pw_action: 'open' | 'message' | 'offers' | 'lead' | 'error',
  pw_turn, pw_count, pw_kind, pw_first, pw_has_offer, pw_where }
```

ב-GTM: **Variables** → Data Layer Variables בשם `pw_action`, `pw_count`,
`pw_kind` → **Trigger** → Custom Event בשם `pw_bot` → **Tag** → GA4 Event,
Event Name `{{pw_action}}`, פרמטרים לפי המשתנים. כך רואים בדוחות כמה נפתחו,
כמה קיבלו הצעות וכמה השאירו ליד.

## 6. פיילוט

עמוד אחד (למשל דף יעד אחד) לשבוע. מה בודקים: `npm run review` על הלוג —
כמה תורות לא הובנו ומי ענה על השאר; `server-data/leads.jsonl` — האם לידים
נכנסים; GA4 — יחס פתיחות→לידים. מה שנופל חוזר אלינו כתשובה ב-FAQ או בבדיקה,
ורק אז פותחים לכל האתר.

| מה רואים | למה | מה עושים |
|---|---|---|
| הבועה לא מופיעה | התג לא פורסם, או הטריגר לא חל על העמוד | GTM Preview → לראות אם התג נורה |
| הבועה מופיעה, השיחה נכשלת | `ALLOWED_ORIGINS` לא כולל את הדומיין המדויק (עם/בלי www) | לתקן ב-.env ולהפעיל מחדש |

| הבוט עונה בלי LLM | אין `OPENAI_API_KEY`, או שהתקציב היומי נגמר | `/healthz` מציג `mode` |

## מלאי שמתעדכן לבד

**זו התשובה.** חלון אחד, פעם אחת:

```
npm run watch
```

הוא מסתכל על קובץ ההתחייבויות ב-F: כל דקה. ברגע שמישהו שומר אותו — הבוט
מתעדכן. לא כל כמה שעות: תוך פחות מדקה.

מה זה **לא** דורש: התקנה, הרשאות מנהל, אישור IT, נגיעה במערכת של מישהו.
Node כבר מותקן, והקובץ ב-F: כבר פתוח לך. זה קורא אותו כמו שאת/ה קורא אותו.

הפענוח קורה במחשב הזה. מה שנשלח זה רק ספירות חדרים פנויים, ואותו שער PII
של הבנייה רץ לפני כל שליחה.

```
npm run watch -- "F:\<התיקייה שבה יושב הקובץ>"
```

**מצביעים על התיקייה, לא על הקובץ.** שם הקובץ בעברית ומשתנה בין עונות; מעקב
אחרי שם קבוע נשבר בשקט ביום שמישהו משנה אותו. המעקב בוחר את קובץ האקסל
החדש ביותר בתיקייה, מדלג על קובצי הנעילה של אקסל (`~$...`, שנוצרים ברגע
שמישהו פותח את הקובץ ותמיד נראים החדשים ביותר), ואומר בשורה מפורשת אם
הקובץ התחלף.

נתיב עברי שמוקלד ב-`cmd` עלול להישבר בגלל דף הקוד — עדיף PowerShell, או
פשוט להשתמש בבורר הקבצים למטה ולא להקליד אותו בכלל.

### שיישרד גם אתחול

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install-watch.ps1
```

נפתח חלון בחירת קובץ — בוחרים את קובץ ההתחייבויות ב-F:, וזהו. לא מקלידים
נתיב בעברית בכלל.

יוצר משימה שרצה מרגע ההתחברות למחשב, **תחת המשתמש שלך** — בלי הרשאות מנהל
ובלי לגעת בשום דבר משותף. להסרה: `Unregister-ScheduledTask -TaskName "Pingwin inventory watch"`.

**המגבלה היחידה:** זה רץ כשהמחשב שלך דלוק. זה מכסה את שעות העבודה, שזה
כשהקובץ משתנה. לכיסוי מלא צריך שזה ירוץ על המחשב שמארח את F: — וזה מה
שדורש אישור, בסעיף האחרון של המסמך הזה.

## עדכון מלאי מהדפדפן — בלי להתקין כלום

**זו הדרך שלא דורשת אישור משום אחד.** פותחים בכרום, במחשב שיש בו את F:.

היום, לפני שיש שרת — מריצים `npm run dev` ופותחים:

```
http://localhost:8787/inventory
```

בלי `INVENTORY_TOKEN` השרת מקבל עדכון **מהמחשב של עצמו בלבד**, והדף לא מבקש
מפתח. זה לא פרצה: מי שיכול לפתוח סוקט ל-127.0.0.1 של המכונה כבר קורא את
הקבצים שהנקודה הזאת כותבת. עם `TRUST_PROXY=1` המסלול הזה נסגר לגמרי, כי
מאחורי פרוקסי *כל* בקשה נראית מקומית.

וכשיהיה שרת: `https://bot.pingwin.co.il/inventory`, עם המפתח.

גוררים את קובץ ההתחייבויות לתוך הדף. זהו.

**הקובץ לא נשלח לשום מקום.** הפענוח קורה בתוך הדפדפן: הדף פורק את ה-ZIP
של האקסל, קורא את הגיליונות, מזהה איזה חדר פנוי לפי צבע התא — הכול במחשב.
מה שנשלח בסוף הוא רק רשימת החדרים הפנויים, ורואים אותה על המסך לפני
שמאשרים.

זה **אותו קוד פענוח** שרץ בבנייה בצד השרת (`tools/xlsx-read.js`,
`data/inventory.js`, `data/aggregate.js`, `data/pii-gate.js`) — נטען לדפדפן
כמו שהוא דרך `/mod/...`. הדפדפן מספק רק פריקת ZIP משלו, כי `zlib` קיים רק
ב-node. `tests/test-inventory-page.js` מריץ את הדף בכרום אמיתי מול קובץ
ההתחייבויות האמיתי ומוודא שהתוצאה **זהה בית-בית** לזו של הבנייה — אחרת,
מי שפתח את הקובץ באותו בוקר היה קובע מה הבוט מוכר.

מה שצריך: כרום (או Edge/Safari עדכני), הקובץ, והמפתח (`INVENTORY_TOKEN`).
לא Node, לא הרשאות מנהל, לא משימה מתוזמנת, לא IT.

**מגבלה אחת שכדאי להכיר:** מישהו צריך לזכור לעשות את זה. אחרי 12 שעות בלי
עדכון הבוט מפסיק לומר "נשאר חדר אחד" ומוסיף שורה על זמינות משתנה — אבל זה
פתרון לתסמין. האוטומציה למטה היא הפתרון, כשיהיה אישור.

## מלאי חי: לחבר את טבלת ההתחייבויות לבוט

קובץ ההתחייבויות יושב על **כונן F:** — שיתוף פנימי בין מחשבי המשרד. השרת של
הבוט לא יכול להגיע לשם, ולכן **המשרד דוחף** במקום שהשרת ימשוך.

```
F:\...\commitments-winter-2027.xlsm
   │
   │  (רץ על מחשב במשרד, כל 3 שעות)
   ├─ node tools/build-availability.js   → מפענח, מסנן, שער PII
   │                                       ↳ נכשל = שום דבר לא נשלח
   ├─ data/availability.json             → יחידות פנויות בלבד, בלי מידע אישי
   └─ POST https://bot.pingwin.co.il/api/inventory
                                          ↳ רק זה עובר ברשת
```

**הקובץ המקורי לא עוזב את הרשת של החברה.** יש בו שמות של לקוחות שהזמינו;
המפענח רץ במשרד ומה שנשלח הוא רק ספירות של חדרים פנויים.

### בשרת

```bash
INVENTORY_TOKEN=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
# להכניס ל-.env, ולהעביר את אותו ערך למחשב במשרד
```

השרת דוחה דחיפה ש: אין לה טוקן נכון · נופלת בשער ה-PII · איבדה יותר מחצי
מהמלאי (קובץ שבור או שמור באמצע עריכה) · ישנה מזו שכבר יש · בלי חותמת זמן.
הקובץ נכתב אטומית, והשרת טוען אותו מחדש **בלי הפעלה מחדש**.

לבדוק מה המצב בכל רגע:

```bash
curl https://bot.pingwin.co.il/api/inventory
# {"generated_at":"...","age_hours":2.4,"stale":false,"units":771,"last_push":{...}}
```

### במשרד

ההוראות המלאות בראש `tools/push-availability.ps1`. בקצרה: Node.js, clone של
הפרויקט, שני משתני סביבה (`PINGWIN_BOT_URL`, `PINGWIN_BOT_TOKEN`), ומשימה
ב-Task Scheduler עם **"Run whether user is logged on or not"** — אחרת היא לא
תרוץ כשאף אחד לא מחובר.

**להריץ את זה על המחשב שמארח את F:** (השרת או ה-NAS), לא על תחנה של עובד.
מחשב שנכבה בערב = מלאי שנתקע בשקט, וזה בדיוק הכישלון שהמנגנון הזה נועד למנוע.

### כשהמלאי בכל זאת מתיישן

אין תדירות רענון שמבטלת את המרוץ — בין שתי דחיפות חדר יכול להימכר. אחרי
`INVENTORY_STALE_HOURS` (12 כברירת מחדל) הבוט:

- **מפסיק לומר "נשאר חדר אחד מהסוג הזה"** — השורה שהכי מהר הופכת לשקר, וגם
  זו שדוחפת לקוח להחליט.
- מוסיף שורה אחת: המלאי מתעדכן כמה פעמים ביום, החדרים פנויים נכון לעדכון
  האחרון, והנציג מאשר סופית.
- ההצעות עצמן נשארות. מלאי בן יומיים עדיין נכון ברובו המכריע.

`logs/push-availability.log` על המחשב במשרד מתעד כל ריצה, וקוד יציאה שונה
מאפס מסמן את המשימה ככושלת ב-Task Scheduler (אפשר לחבר לזה מייל).
