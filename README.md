# 🐧 בוט התאמת חופשות סקי — פינגווין (דמו)

צ'אט צף בעברית לאתר פינגווין: הלקוח כותב בשפה חופשית, הבוט משלים מה שחסר
בשאלה-שתיים לכל היותר, ומציג **3 חבילות אמיתיות שפנויות בפועל** מתוך קובץ
ההתחייבויות של חורף 2026/27.

## הרצה מקומית

```bash
node server/server.js
```

ולגלוש אל: **http://localhost:8787**

זהו. בלי התקנות, בלי תלויות — Node בלבד.

| מצב | מה צריך | איך זה מבין עברית |

### חיסכון בטוקנים — איך זה עובד

1. **שכבת העברית רצה קודם, תמיד, בחינם.** מודל נקרא **רק** כשהיא לא הבינה את ההודעה.
   תשובות קצרות, לחיצות על צ'יפים, "4 ו-9", "ינואר" — לא עולים כלום.
2. **קריאה אחת לתור, לא שתיים.** ניסוח התשובה נעשה בתבניות.
3. **פרומפט רזה** (~400 טוקנים במקום ~1500) + `response_format: json_object`.
4. **היסטוריה מקוצרת** — רק 4 ההודעות האחרונות נשלחות; השאר כבר מקופל ב-slots.
5. **מונה עלות בלוג**: כל קריאה מדפיסה טוקנים ועלות מצטברת בשקלים.

בונוס בטיחות: המודל **לא רואה את המלאי בכלל**. הוא ממלא שדות בלבד, ולכן פיזית
לא יכול להמציא מלון, תאריך, מחיר או זמינות.

### הטמעה דרך Google Tag Manager

הקובץ [public/gtm-tag.html](public/gtm-tag.html) מכיל את התג המוכן. בקצרה:

1. GTM → Tags → New → **Custom HTML**
2. הדביקו את תוכן הקובץ, והחליפו את `BOT_HOST` בכתובת השרת (HTTPS!)
3. Triggering → **All Pages**
4. Save → Submit → Publish

לפני זה צריך: השרת מותקן בכתובת ציבורית עם HTTPS, ו-`ALLOWED_ORIGINS` ב-`.env`
מוגדר לדומיין של פינגווין (לא כוכבית).

## הטמעה באתר האמיתי

שורה אחת לפני סגירת ה-`</body>`:

צבעים ופונט: אובייקט `THEME` בראש `public/pingwin-bot.js` (פלייסהולדרים לצבעי פינגווין).

## נתוני חדרים מאתר פינגווין

קובץ ההתחייבויות מכיר קוד חדר ותפוסה בלבד. כל השאר — מיטות, גודל, חדרי רחצה, בסיס אירוח, הסעות וסקי פס — נלקח מדפי המלונות ב-pingwin.co.il (חוק אדום 5).

- `data/rooms-raw.json` — 40 מלונות, 103 סוגי חדרים, מילה במילה מהאתר
- `tools/merge-rooms.js` — ממזג אל `data/resorts.json` (חלק מ-`npm run build:data`), ונופל אם יש בו מספר הזמנה
- `data/room-match.js` — מתאים בין שם החדר בקובץ ("J. Suite 2+1") לחדר שבאתר. שמרני בכוונה: כששני חדרים מתאימים באותה מידה הוא מוותר ומשאיר לנציג לאמת. מתחשב בגודל החבורה ("DBL 2-4" הוא חדר אחר לזוג ולמשפחה של ארבעה)
- `config/inclusions.json` — מה כלול ומה תוספת (טיסות והסעות תמיד; סקי פס למעט בולגריה; ציוד כלול במועדוני השמש)
- `tests/test-rooms.js` — שומר שהבוט לא ממציא חדר, לא מבטיח סקי פס בבולגריה ולא נוקב מחיר ציוד

דרישות שהלקוח מציין (מיטות נפרדות, ארוחת בוקר, נסיעה קצרה מהשדה) לא רק נענות — הן משפיעות על סדר ההצעות (`_requirementScore`). הן לעולם לא מסננות הצעות החוצה — הקובץ מחליט מה פנוי, ורק הוא.

## חלוקת העבודה עם המודל (עודכן 24/08/2026)

**הקוד קובע מה נכון. המודל קובע איך אומרים את זה.**

קודם לכן המודל נקרא רק כששכבת ה-regex לא הבינה כלום, והניסוח היה תבניות. זה היה זול
ומתסכל: כל ניסוח שלקוח המציא היה באג חדש לתקן ביד.

- **הבנה** — המודל קורא כל הודעה אמיתית. חינם נשארו: מספר בודד, כן/לא, לחיצת צ'יפ,
  והודעה קצרה ששכבת ה-regex הבינה במלואה.
- **ניסוח** — המודל כותב את התשובה, אבל **רק מעל ההצעות שהקוד כבר בחר**.
  הוא לא רואה את המלאי, ולכן אין מאין להמציא מלון או תאריך.
- **מה נשאר דטרמיניסטי לחלוטין** — מה פנוי, אילו תאריכים, תפוסה, שבת,
  כיסוי קייטנות, מחירים. שם טעות עולה כסף.

`server/prompt-phrase.js` מחזיק את ה-prompt ואת `validate()`. כל פלט שלא עובר אותו — מחיר
במספרים, מלון שלא הוצע, תאריך שהומצא, הבטחת זמינות, שעת טיסה, "הכי טוב" —
**נדחה, והניסוח התבניתי נשלח במקומו**. התבנית היא הרצפה, לא התקרה.

עלות בפועל: כ-0.01₪ לשני תורים (4 קריאות, gpt-5.6-luna), כלומר שבריר שקל לשיחה מלאה.

## לוג שיחות

כל באג בפרויקט הזה נמצא כשאדם קרא תשובה. חבילת ההקשיה בת 83 התרחישים
דיווחה "נקי" בכל סבב. הלוג מחליף את ההמתנה לצילום מסך.

- `server/conversation-log.js` — שורה לכל תור, ב-`logs/chat-YYYY-MM-DD.jsonl`
- `npm run review` — מדפיס רק את השיחות שמשהו בהן לא הלך טוב
- סינון: `node tools/review-log.js today dead_end` (ללא הצעות), `deferred` (הופנה לנציג),
  `objection` ("יקר לי"), `widened` (נדרשה הרחבה), או `all`
- לכיבוי: `CHAT_LOG=off`

**מה לא נכתב** (סעיף 2a): שם וטלפון מטופס הליד, שמות לקוחות מהקובץ,
מספרי הזמנה. מזהה השיחה הוא מחרוזת אקראית. בדיקה נופלת אם רצף של 6 ספרות
מגיע ללוג. תקלה בכתיבה לעולם לא שוברת שיחה.

## הנחיות לבוט — קובץ שתומר עורך

`config/guidance.json` — מה לשאול, באיזה סדר, איך לענות, מה להדגיש בכל יעד ומה אסור.
עברית פשוטה, בלי קוד. **נטען מחדש אוטומטית בכל שמירה** — אין צורך להפעיל מחדש את השרת.

- `ask_priority_he` / `ask_never_he` — נכנס לפרומפט שמבין את הלקוח ומחליט מה לשאול
- `answer_tone_he` / `answer_length_he` / `answer_always_he` / `answer_never_he` — נכנס לפרומפט שמנסח
- `emphasis_by_country_he` — מה להדגיש כשההצעות ביעד מסוים
- `lead_he` — מתי להציע שנציג יחזור

**מה הקובץ הזה לא יכול לעשות:** לרכך חוק אדום. ההנחיות של תומר נכתבות ראשונות
והכללים הקשיחים אחריהן, ו-`validate()` בודק את הפלט בלי קשר למה שכתוב בפרומפט.
בדיקה ב-`tests/test-guidance.js` משבשתת את הקובץ בכוונה ("תמיד תנקוב במחיר בשקלים")
ומוודאת שהפלט עדיין נדחה. שגיאת עריכה יכולה לעשות את הבוט פחות טוב במכירה.
היא לא יכולה לעשות אותו לא בטוח.

## מדידה עם המודל (--live)

בנק השאלות רץ כברירת מחדל **offline** — שני המפתחות מנוטרלים בכוונה, כך שהרצה
מלאה חינמית ומודדת רק את השכבה הדטרמיניסטית. לכן הציון יציב ואפשר להשוות
הרצות. אבל בייצור יש מודל, ובעיקר יש **נתב סמנטי** שקיים בדיוק בשביל ניסוחים
שהתבניות לא מכירות — והוא בלתי נראה בהרצה offline.

```bash
node tests/test-bank.js                       # offline, חינם, קו הבסיס
node tests/test-bank.js --live --stuck        # רק מה שנתקע offline (הכי משתלם)
node tests/test-bank.js --live --sample=150   # פרוסה קבועה
node tests/test-bank.js --live                # כל 1,215 השאלות
```

אפשר לעצור באמצע ב-Ctrl+C — הבנק ידפיס סיכום על מה שכבר נמדד ויסמן אותו
כ"הרצה חלקית", במקום לזרוק את העבודה. Ctrl+C שני עוצר מיד.

`--live` דורש מפתח ב-`.env`. התוצאות נשמרות ל-`tests/bank-results-live.json`
כדי לא לדרוס את קו הבסיס. מחיר: הדגם הזול הוא $0.20/$1.20 למיליון טוקנים,
כלומר הרצת `--stuck` מלאה עולה סנטים בודדים.
